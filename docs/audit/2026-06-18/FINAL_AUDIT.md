# Ollie Monorepo — Final Triple-Audit Report

**Date:** 2026-06-18
**Method:** 20 lanes × 3 blind rounds. Confidence = how many of the 3 independent rounds reported the same underlying issue (3 = strongest signal, all agreed; 1 = only one round saw it).
**Ordering:** Severity tier first (critical > high > medium > low), confidence as the weight inside each tier.

---

## 1. Executive Summary & Verdict

**Verdict: NOT alpha-ready. The encrypted-sync write path is broken end-to-end, the identity model is split (uuid vs Clerk text), and the two costliest AI endpoints have no rate limit.**

Three independent audit rounds converged hard on a small set of show-stoppers. The single most damaging cluster is the **encrypted sync pipeline**: clients send base64 into Postgres `bytea` columns (rejected by the IV `octet_length=12` CHECK), the `encrypted_state` upsert omits `on_conflict` (every 2nd+ push 409s), and the `/route/:module` routing cache is fully dead (missing RPC + missing column) so every classify call pays full Groq cost. Layered on top, six core tables key on Supabase `uuid`/`auth.users` while the app authenticates with **Clerk text ids** — so server reminders, finance sync, Plaid, and push-token registration silently fail for real users, and the app-closed cron→APNs path has no tokens to push to.

All three rounds independently flagged: the missing rate limit on `/route/dump` + `/route/:module`, the missing client `dumpId` idempotency key (timed-out-but-succeeded dumps double-write), the per-module migration promise that caches a rejection and bricks the module for the session, the finance cursor advancing past decrypt failures (permanent data loss), the inbound-sync echo/watermark corruption loop, the time-windowed work/goals cues that never fire on a timer, the dead `hit_count` increment, the PII empty-after-scrub gate that misses sensitive-category tokens, the crisis lexicons still `PENDING_SERRA_APPROVAL`, and a large body of UI/reinvented-wheel debt (RemoveButton ×11, formatDays ×9, SMCP style ×15-19, no shared data-load/poll hook, oversized 1000-1349-line Box god-files, dead ledger migration runner).

Plaintext SQLite at rest for health/finance/mood data, an unauthenticated Sentry open relay, Clerk JWT verification missing the `azp`/`aud` check, and iOS ATS arbitrary-loads round out the security gaps. The good news: most criticals are concentrated in two subsystems (sync wire-format + identity) and are fixable without a redesign; almost nothing is live to external attackers yet (workers are JWT-gated, `apps/api` is undeployed).

## 2. Methodology

- **20 lanes** spanning: worker AI routing & cost, sync/crypto, native dump flow, native modules/handlers, orchestrator cues/cadence, logic/stats detectors, store, notifications, DB/migrations/RLS, PII-scrub, crisis, UI/design-system, Tauri/iOS security, cron/queues, apns-push.
- **3 blind rounds** — each round audited independently and produced a deduped result set (R1: 92, R2: 87, R3: 92 issues).
- **Confidence = round-agreement.** Issues were matched across rounds by meaning + location, not by key string. A `confidence-3` high-severity issue outranks a `confidence-1` one of the same severity.
- Severity is the auditors' rating; where rounds disagreed on severity, the **highest** severity assigned by any round is used and noted.
